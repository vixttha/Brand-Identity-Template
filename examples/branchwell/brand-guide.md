# Branchwell brand and interaction guide

**Name** Branchwell, pronounced “branch-well.” **Descriptor** A workspace for your GitHub repositories. **Tagline** Your repositories. Your next move.

Branchwell serves an individual managing many repositories across personal builds, reusable tools, experiments and ongoing maintenance. It should make the next action feel obvious. Use concrete verbs such as “Sync GitHub,” “Save profile,” and “Open work mode.” Use plain counts and dated evidence. Avoid ranking people or projects by raw activity.

## Visual identity

The mark uses two overlapping filled circles with uppercase **B** and **W**. The full lockup pairs the mark with the Branchwell wordmark in sentence case. Use the full lockup in navigation and documentation. Use the mark alone only where “Branchwell” is supplied as accessible text. Use 29px circles in compact navigation and 37px in the desktop rail. Leave clear space of at least one quarter of the diameter around the lockup.

Use Instrument Sans where available with Segoe UI and Arial fallbacks. Titles use a tight, bold type scale. Controls are compact and explicitly labeled. Charts use paired bars on a shared zero baseline, their period totals in the legend, and an accessible weekly data table. Status and visibility use text so color is supplementary. Mobile puts navigation above the content and can hide metadata columns that are always available in a profile.

## User flow

**Sync GitHub → Overview → Repositories → Repository profile → Save profile → Work mode.** Use Activity for trend and repository-level PR context. Use Settings to confirm account and storage state. Profile links use URL fragments for direct navigation within the same workspace. Filters stay in memory per directory during navigation. Profile edits persist locally across restarts. The static demo uses fictional data and browser storage.

The name and lockup are the project working identity. A trademark clearance and a registered domain are separate decisions.
